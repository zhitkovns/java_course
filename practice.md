Разница в результатах происходит из-за **статического (compile-time) разрешения перегрузки**.

## В цикле for (1):
```java
for (Number n : num) {
    a.printNum(n);  // Тип переменной n - Number (на этапе компиляции)
}
```
**Компилятор** видит, что тип параметра `n` - `Number`, и выбирает наиболее подходящий метод:
- `printNum(Number n)`. Остальные методы не рассматриваются, так как компилятор не знает фактический тип объекта во время компиляции.

## В явных вызовах (2):
```java
a.printNum(new Integer(1));  // Компилятор видит Integer -> printNum(Integer i)
a.printNum(11);              // Компилятор видит int -> printNum(int i)  
a.printNum(1.11f);           // Компилятор видит float -> printNum(Float f)
a.printNum(11.11);           // Компилятор видит double -> printNum(Number n)
```

**Почему разные результаты:**
- В цикле: тип определяется на этапе **компиляции** как `Number`
- В явных вызовах: компилятор знает точный тип каждого аргумента и выбирает наиболее специфичный метод

**Вывод будет:**
```
// Цикл for (1) - все вызовы printNum(Number n)
Number=1
Number=11
Number=1.11
Number=11.11

// Явные вызовы (2) - разные методы
Integer = 1
int = 11
Float = 1.1100
Number=11.11
```
